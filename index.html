Repository

Let agents act freely, until they shouldn't.

Throttle is an external authority controller for long-running onchain agents. It scores every proposed payment for risk, checks it against the agent's own behavioral baseline, and decides — in real time — how much the agent is allowed to do right now.

Overview
Static permission thresholds can't tell whether today's transaction is normal or the start of a problem. Throttle replaces the fixed limit with a decision that adapts to what the agent has actually been doing.
6 distinct authority levels, from full autonomy to frozen
2 independent gates the agent's payment has to clear

The problem

Agents don't fail all at once. They drift.

An agent that behaved safely for its first thousand actions can gradually start moving larger amounts, hitting unfamiliar destinations, or retrying failed calls more often. A fixed dollar limit has no way to tell "normal today" from "suspicious today."

The solution

Three scores, kept deliberately separate

Risk, trust, and authority answer different questions and are never collapsed into one number. An agent can be highly trusted and still have a single risky action held back.

Risk

How dangerous is this action?

Scored 0–100 from the proposal itself: amount, destination novelty, protocol familiarity, and current frequency. Every score returns a labeled breakdown, not a bare number.

Trust

How reliable has this agent been?

Built from the quality of recent behavior, not the volume — violations and drift cost more than clean actions earn. Decays on a 24-hour half-life, so it's never a permanent badge.

Authority

What is it allowed to do right now?

Combines risk, trust, drift, and hard policy into one of six levels — and moves the agent between them automatically as conditions change.

Architecture

The agent proposes. The controller authorizes.
KeeperHub executes.

Throttle never signs anything itself. It decides whether a signature should be requested at all — execution stays entirely inside KeeperHub's Turnkey-backed wallet infrastructure.

01
Daydreams agent

Proposes a payment on TaskMarket — a bid, a claim, a task acceptance.

02
402 challenge received

TaskMarket returns the real amount, payee, and nonce for the payment.

03
Throttle controller

Risk, trust, and drift are evaluated against the agent's own history.

04
KeeperHub signs

Only if authorized — Turnkey produces the EIP-3009 signature.

05
Settlement

Signature is returned to TaskMarket and the payment settles onchain.

Gate 1 — coarse

A PreToolUse hook checks the proposed action at tool-call time, before any payment amount exists yet.

Gate 2 — fine-grained

Once the real 402 challenge is known, Throttle evaluates the actual amount and destination before a signature is ever requested.

Even when Throttle says allow, KeeperHub's Turnkey policy — contract allowlist, per-transfer cap, daily cap — remains the final, deterministic floor.

How it works

One evaluation, five layers, one decision

Every proposed action passes through the same pipeline, in the same order, every time. The output is always reproducible from the same inputs.

01

Hard policy check

Deterministic limits — max transfer, allowed chains and protocols, actions per hour — that no score can override.

02

Risk scoring

The proposed action is scored on amount, destination novelty, protocol familiarity, and current frequency.

outputs a labeled factor breakdown
03

Drift detection

Current behavior is compared against the agent's own established baseline — size, velocity, destination spread.

04

Trust update

Recent behavior quality adjusts a decaying trust score — violations and drift cost more than clean actions earn back.

05

Authority decision

All four signals combine into one of six authority levels, with a plain-language reason attached to the audit record.

deterministic — never decided by an LLM
